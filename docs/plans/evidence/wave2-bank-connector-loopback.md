# Wave 2 synthetic bank connector loopback proof

Revision: `fce7af7aa75792bfe02d16ec898cf0c5fa15311a` (working tree contains unrelated concurrent changes). Date: 2026-09-24. Local PostgreSQL 17 initialized under a disposable temporary directory at port 55473; synthetic book provisioned via `bun apps/api/scripts/provision.ts examples/synthetic-book.json`. Applied SQL `7300`, `7800`, `8400` through `bun apps/api/scripts/migrate.ts`. No actual Plaid credentials or network requests were used. Plaid response bodies were synthetic JSON manually retained through the real HTTP source-intake endpoint. All dummy provider credentials used by Bun CLI were deliberately nonfunctional. No test file was added; this record is the repeatable evidence artifact.

## Reproduction outline

1. In a fresh disposable PostgreSQL cluster, set `DATABASE_ADMIN_URL`, migrate, run `bun apps/api/scripts/self-host-role.ts` with a random `OPENERP_RUNTIME_PASSWORD`, and provision the synthetic manifest with a fresh scoped `OPENERP_ACCESS_TOKEN`.
2. Start `bun apps/api/scripts/self-host.ts` with the restricted `DATABASE_URL` and `BETTER_AUTH_SECRET`, first _without_ `OPENERP_OBJECT_DIRECTORY`, then with a private, canonical absolute directory (on macOS use `/private/var/...`, not `/var/...` because the latter is a symlink).
3. Create the Plaid consent via `POST /api/v1/entities/entity_synthetic/books/book_synthetic/bank-connector-consents` with `externalAccountId=plaid_account_synthetic`, `sourceAccountId=bank_synthetic`, `accountId=account_bank` and separate synthetic attestation. Retain a synthetic `/transactions/sync` JSON response as `connector-raw:plaid` through `POST .../source-occurrences`, using `occurrenceKey=plaidraw_<first 48 hex of SHA256("book_synthetic:<consentId>:<previousCursor>")>`, and `sourceRevision=SHA256(raw bytes)`.
4. To exercise Worker HTTP, start `apps/api/node_modules/.bin/wrangler dev --config <private-temporary-wrangler-config> --local --ip 127.0.0.1 --port <loopback-port> --persist-to <private-temporary-state>` with Worker `vars` (`DATABASE_URL` restricted URL, `BETTER_AUTH_URL` loopback origin, `BETTER_AUTH_SECRET` random) and `r2_buckets: [{"binding":"EVIDENCE_BUCKET","bucket_name":"synthetic-bank-probe"}]`. Without that R2 binding, retention and original retrieval fail closed at HTTP 503. Wrangler may print environment variable prefixes: treat startup logs as secrets and delete them after use.
5. Set a mode-0600 operator config JSON _outside the repo_, `apiOrigin` pointing to Worker loopback, matching entity/book/consent/account, dummy nonempty `host/clientId/secret/accessToken`, and `OPENERP_CONNECTOR_TOKEN` to the scoped synthetic API token. **Retain the matching raw page before running CLI** so it recovers locally rather than calling Plaid. Run `bun apps/api/scripts/bank-connector-sync.ts /absolute/private/config.json`. Query Worker consent/batch/source original and PostgreSQL tables to compare digest, cursor and receipt. Stop Wrangler and PostgreSQL, remove all temporary secrets/data.

## Observed receipts and refusal boundaries

- Bun self-host HTTP without `EVIDENCE_STORE`: source POST 503 `Unavailable`; source recovery 404; consent cursor empty. With private file store: source POST 200, exact raw occurrence and digest retained.
- For empty cursor, a different occurrence with the **same digest and source account** but wrong occurrence key was retained; batch POST returned 422 `MissingEvidence`, cursor stayed empty. Correct original then committed 200 with `recordCount=1`, `recognition=not_admitted` and cursor `cursor_synthetic_1`.
- Replaying that original idempotency key and payload after cursor advanced returned HTTP 200 with the same batch ID. A fresh key with stale previous cursor returned 422 `InvalidJournal`.
- With next cursor `cursor_synthetic_2`, an `uncertain` provider outcome with no records returned 200 and preserved the cursor. After a third original was retained but before batch POST, disabling its mapped account in this disposable database returned 409 `StaleDependency`; cursor stayed `cursor_synthetic_2`. Reenabling account and running the CLI recovered that retained page and committed `cursor_synthetic_3`.
- Worker HTTP **without** object storage returned consent and batch receipts at 200 but original GET and new source POST returned 503 `Unavailable`; cursor stayed `cursor_synthetic_2` at that point.
- Worker HTTP **with** local R2 binding: source POST and source-key recovery returned 200. Original GET bytes SHA-256 matched source revision `0cff2c58e45d7d41982d19642446573ba84b35d3c8e91633e152a6463e4b9a31`. Bun CLI pointed at this Worker, recovered the synthetic removed-update page and committed batch `connectorbatch_23971acdcc3c41bb9b4b7a03fb2108ea`, `sourceOccurrenceId=source_96f12d63e7cc4c8fa1e58d35a329ffe1`, `previousCursor=cursor_synthetic_3`, `nextCursor=cursor_synthetic_4`, `recordCount=1`, `recognition=not_admitted`, `providerVerification=not_established`. PostgreSQL counts: 5 connector batches (4 delivered + 1 uncertain), 4 connector records, 5 raw-page occurrences (one deliberately wrong), 4 record occurrences; persisted cursor `cursor_synthetic_4`.

## Remaining gates

- Local R2 simulation does not prove hosted storage durability, backup/recovery, access policy or production Worker credentials (D-07).
- The repository Wrangler config does not currently bind `EVIDENCE_BUCKET`; a configured private R2 bucket (or equivalent `EVIDENCE_STORE`) must be supplied in the actual Worker environment. The no-storage failure is intentional and closes before cursor movement.
- No Plaid request, account/token scope, response semantics, pagination mutation recovery, provider consent or acceptance was observed (D-10). Synthetic HTTP JSON has no provider signature. The CLI cannot auto-restart a committed pagination window on Plaid `TRANSACTIONS_SYNC_MUTATION_DURING_PAGINATION`; operator review remains required.
