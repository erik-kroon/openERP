# Local synthetic legal PDF delivery-outbox E2E

Observed 2026-09-24 from the real Worker HTTP boundary and fresh disposable PostgreSQL 17. All 35 HTTP checks in `observations.json` met their expected status. `sealed-v2.pdf` is the immutable synthetic PDF; its SHA-256 and byte count are in the JSON. No provider was called and no delivery was claimed. Accepted/rejected/not-sent reconciliation labels were mock records for exercising the state machine, **not provider facts**.

## Reproduce safely

1. Create an isolated PostgreSQL 17 cluster/database; set `DATABASE_ADMIN_URL` to that disposable database only. Run `bun run --cwd apps/api db:migrate` (144 migrations at observation time). Provision `examples/synthetic-book.json` with a fresh scoped token using `bun run --cwd apps/api db:provision ../../examples/synthetic-book.json`. Prepare and approve a **synthetic** legal issue with three distinct operators as described in [the legal PDF Worker record](../wave2-legal-pdf-worker.md). The original exercise used an untracked local SQL fixture; it is not a production seed or a checked-in test. Never run synthetic setup against a non-disposable database.
2. Run `bun apps/api/scripts/self-host-role.ts` with a random `OPENERP_RUNTIME_PASSWORD` (32+ chars). Start a local Wrangler Worker with `apps/api/src/runtime/cloudflare.ts`, the project's pinned compatibility settings, and a temp `.dev.vars` outside the checkout: `DATABASE_URL` must use **openerp_app**, not maintenance credentials. Keep all credentials out of saved logs/artifacts.
3. Use three distinct fixture operators with scoped bearer HTTP calls to `/api/v1/entities/entity_synthetic/books/book_synthetic/commerce`. Every POST uses a fresh `idempotency-key`. Look up the single `ar_legal_issues` id and digest in the disposable database; POST `/legal-invoice-pdfs` with `issueId`, `issueDigest`, `rendererVersion: openerp-se-invoice-takumi-v2`. Verify decoded `artifact.contentBase64` has `%PDF-`, reported byte length and SHA-256; repeat same key, GET the PDF and POST `/legal-invoice-pdfs/:id/render`.
4. POST `/legal-deliveries` with exact PDF `pdfCaptureId`, `captureDigest`, `artifactSha256`, `channel: email`, a reserved `.invalid` destination, `providerProfileKey: synthetic_no_network`, and a reason. Check `awaiting_send_approval`. The creating operator's POST `/:id/send-approval` must fail. A **different** operator approves the request digest with `approveSendHandoff: true`. That approving operator POSTs `/:id/provider-attempts` with request digest, approval ID, provider key, `acknowledgeUncertainBoundary: true`: verify `provider_unknown`, a durable `providerRequestId`, and `externalTrafficProven: false`. Never transmit that request to a provider.
5. Check a second different-key attempt is blocked while unknown and same-key replay retains its original response. Create local synthetic text evidence via scoped POST `/evidence`; using the third operator, POST `/legal-delivery-attempts/:id/reconcile` with saved attempt digest/request ID, evidence ID/hash, nullable provider message ID, and `confirmed_not_sent`. Treat this as mock state-machine input, not factual provider reconciliation. A new attempt is admitted with a new request ID and ordinal 2. Same reconciliation key replays its saved snapshot; another key cannot overwrite it. Test separately prepared destinations for mock `provider_accepted` (non-null synthetic message ID) and `provider_rejected` (null message ID); neither permits a new attempt and neither sets `delivered`. Peppol approval remains `peppol_payload_blocked`, with attempt POST denied.
6. GET `/legal-deliveries/:id` and `/legal-invoice-pdfs/:id/deliveries`; cross-book GET and POST with a bogus book must fail 403. Direct database count query: `SELECT (SELECT count(*) FROM openerp.ar_legal_pdf_captures), (SELECT count(*) FROM openerp.ar_legal_pdf_artifacts), (SELECT count(*) FROM openerp.ar_legal_delivery_requests), (SELECT count(*) FROM openerp.ar_legal_delivery_approvals), (SELECT count(*) FROM openerp.ar_legal_delivery_attempts), (SELECT count(*) FROM openerp.ar_legal_delivery_reconciliations);` Expected `1|1|4|4|4|3`. Destroy disposable Worker/database and temp `.dev.vars` afterward.

No external provider acceptance, actual sender identity, email payload format, transport idempotency, delivery to a customer, deployed Worker behavior, or production tenant authority was verified. The mock `confirmed_not_sent` record must **never** justify a real retry without actual independent provider evidence.
