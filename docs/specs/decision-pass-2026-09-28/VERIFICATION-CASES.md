# First verification tranche

Selected under the bounded engineering policy. These are acceptance requirements, not results observed by this decision pass. Bind them to existing tests and owners instead of building a new harness product. The first complete source-supported workflow is the priority.

## Required conformance cases

Exact positive/negative/zero money, upper/lower wire bounds, numeric rather than lexical ranges, cumulative component release, a positive floor remainder, a negative exact floor division, leap/invalid dates and exact body-versus-column/canonical-hash agreement. Assert expected byte and numerical outputs independent of the production function.

Include outer versus nested rule decoding, object versus array fields, stable source/component IDs across two invoices with identical local line IDs and approval-body versus reviewed-plan hash meaning. Static compilation alone does not exercise these representation boundaries.

## Required application journeys

1. Supported purchase recognition with two lines and partial input-tax deduction, then two valid partial supplier credits. Reconcile payable, tax components, adjustment references, original source capacities and all shared readers.
2. Customer invoice, partial payment, valid legal credit and correction. Keep invoiced, payable/receivable, paid, refunded and reported states separate.
3. Company-bank settlement of an already recognised invoice through its actual released owner. A bank-to-ledger reconciliation link is not automatically that invoice settlement. If the necessary port is absent, complete the old owner under its original ID.
4. Owner-funded expense or discharge when part of the selected profile: company cash unchanged until actual reimbursement, no second cost/VAT and a shared payable residual that agrees everywhere.
5. Accrual baseline and a separate cash-method case with partial payment, unpaid year-end recognition and later payment without double recognition. Do not silently switch one company's historical method.
6. Existing exact allocation prepare/approve/execute, competing consumption, mismatch refusal and replay. Observe that execution, legs, source revision and command receipt are atomic in the actual adapter.
7. SIE/report/archive capture and retained artifact recovery, followed by independent source/control comparison and isolated restore. File generation, parse acceptance and whole archive restorability are distinct.

## Required failure neighbours

For each relevant operation, test current scope and private permission, wrong book, revoked actor, expired unconsumed approval, same successful-key recovery, changed input under the same key, different key for the same economic event, stale source/capacity, an interruption after required intermediate writes and ambiguous commit recovery.

The runtime role must have the restricted table grants it actually needs. Do not test that valid application table writes are universally forbidden. End-user isolation belongs to real admission/lookup paths. Immutable structural history belongs to the actual schema. Inspect composed constraints before claiming a missing redundant trigger is a failure.

No source-checker assertion, fake SQL mock, Accounted output copied as an expectation or second AI reviewer replaces the actual observed transaction result. Keep test-plan errors and runtime defects separately classified.

## Evidence record

Retain revision, dependency lock/version, migration checksums, actual runtime/database/role, source/test input hashes, independently specified expected output, observed response and persisted state, coverage and failure traces. Keep meaningful output/errors, not only a passing count.

A successful fixture proves its named scenario. It does not mark every NEXT packet, the whole company, a legal framework or hosted deployment verified. Failed or skipped stages remain visible. Existing real-data and provider permission gates remain in effect.
