# Compliance, interoperability and migration boundaries

Status: planned capability coverage. This document organizes implementation and verification; it supplies no approved tax rates, legal applicability determinations, live credentials or filing guarantees.

The [VAT/payroll/assets/FX plan](plans/05-vat-payroll-assets-fx.md) and [year-end/report/filing plan](plans/06-year-end-reports-filing.md) specify records, transitions, calculations, recovery and delivery packets. [External inputs](plans/10-external-inputs.md) define the exact source/profile/provider dossiers needed for activation. Complete engineering planning does not fill unknown company facts or certify legal treatment.

## Versioned capabilities

Keep company facts, jurisdiction rules, chart releases, report mappings, file schemas, provider protocols and fulfillment evidence separate. Each rule bundle needs a primary source, applicability dates and predicates, required facts, rounding/correction behavior, reviewed scenarios and release evidence. Unsupported facts or treatments are explicit blockers.

Use the [official-source register](sources/README.md) to locate the applicable rule, format and provider material. Preserve exact versions and access limitations through [external inputs](plans/10-external-inputs.md); a research link does not activate a rule bundle.

Prepare readable and tagged output from the same semantic report, never from separately calculated UI totals. Retain non-ledger facts such as meeting dates, signatories and adoption decisions with their actual evidence. Upload, signature and authority acceptance follow the provider's state graph; a generated artifact cannot fulfill an obligation by itself.

Independent validators have bounded coverage. Before selecting one, inspect its pinned implementation and licenses and record which records/rules it checks. SIE correction records, dimensions and encoding require explicit coverage; unsupported records must produce diagnostics or be preserved. An isolated validator process does not by itself settle licensing or compliance.

## Evidence and archive

Store original bytes and verified digests before marking evidence available. Preserve match provenance and prior facts. Retention, storage geography, access and deletion policy require the actual company/deployment arrangement ([D-07](open-decisions.md)). Do not substitute a cloud region label for that decision.

A restore includes the database, original evidence, matches, approvals, correction history, rules/mappings, reports, filing artifacts and receipts. SIE alone is not a complete backup. A successful object upload followed by database failure needs orphan cleanup; the inverse must never produce a posted entry depending on nonexistent evidence.

## Company migration

[ADR 0003](adr/0003-native-accounting-and-migration.md) defines native accounting and the company migration boundary. No actual legacy accounting connection or company export has been established. Establish the actual source/version and data-use permission before choosing an adapter ([D-06](open-decisions.md)).

The preferred migration is an isolated full available history import with source IDs and relationships, followed by independent reconciliation. Preserve official voucher references, historical inline/reversal corrections, prior filing artifacts, unpaid items, schedules, period locks and receipt matches. Missing historical semantics remain labeled unresolved. Old source approvals do not authorize newly interpreted target plans.

Declare reduced-history/opening-only migration explicitly when necessary. Never import both the historical movements and an opening balance representing them. Compare counts, exact totals and balances by year/account/series/currency, plus recognized subledgers, evidence coverage and historical declarations.

Cutover freezes source writes, reconciles the final delta and establishes one authorized writer. Before native writes, a consistent authority switch can be reversed; after native-only effects or submissions, recovery needs a reconciled delta/correction plan. Permanent dual posting and restoring a backup that erases acknowledged effects are outside the design.

All actual-data use, provider access and cutover decisions stay separate from this documentation delivery. No production readiness is claimed.

## Profile and format detail

The following are design and review requirements. Exact statutory rules, applicability, dates and provider sequences require the primary-source release process in [external inputs](plans/10-external-inputs.md) and the [source register](sources/README.md).

| Area                | Required distinctions and edge cases                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Company/framework   | Select framework by actual entity facts, fiscal-year start and applicable transition provisions. Unsupported and missing-facts are separate outcomes. Company elections and learned rules cannot override legal applicability.                                                                                                                                                                                     |
| Charts and mappings | Stable account identity is separate from dated number/name, tax role, SRU role and annual-report role. A valid account code or prefix does not prove appropriate treatment. Preserve historical mapping and inactive-account interpretation.                                                                                                                                                                       |
| VAT                 | Model mixed rates, partial/non-deductibility, exemptions, jurisdiction, reverse-charge basis, credit notes and tax points only within advertised coverage. Foreign VAT is not automatically domestic deductible input VAT. Tax-account transfers, assessments, filing corrections and payments remain distinct.                                                                                                    |
| Payroll             | Retain employment and benefit facts, earning/payment periods, irregular work schedules, tax-table/decision inputs and eligibility at the approved run revision. Later employee changes cannot rewrite it. Reconcile net liability, payment, withholding, contributions and tax-account movements separately.                                                                                                       |
| AGI and KU          | Treat employer/individual identifiers, absence information, correction keys and form/year schemas as separate contracts. Determine whether AGI and a KU family overlap from applicable rules; do not generate declarations merely because data exists. Absence corrections cannot be assumed to follow the ordinary replacement path.                                                                              |
| Payment files       | Retain exact exported bytes, source payroll/payment run, version, hash and authorization. An export timestamp does not establish what was exported or paid.                                                                                                                                                                                                                                                        |
| Tax computation     | Retain permanent and timing adjustments, prior carryforwards, elections and target-field lineage. Corporate tax is not an unconditional percentage of accounting profit. Missing non-ledger inputs block the affected output.                                                                                                                                                                                      |
| Annual reports      | One semantic model owns comparative periods, signed values, disclosures, framework and source/reviewer references. Proposed profit distribution differs from adopted decisions and actual payments.                                                                                                                                                                                                                |
| iXBRL               | Pin concepts, contexts, periods, units, dimensions, decimals/scale/sign and taxonomy. Generate readable and tagged forms from the same model, then run structural, independent semantic and filing-business-rule checks. A parseable document can still contain the wrong statutory facts.                                                                                                                         |
| Signing             | Identity, entity authority, approval of content, signature, digital-copy certification and provider acceptance are separate evidence. Changed bytes invalidate the corresponding approval/signature. Model the selected provider's actual order and pending states.                                                                                                                                                |
| SIE                 | Declare coverage separately for classic variants, full-year type 4, voucher-only 4i and SIE5. Preserve encoding, original record locations, dimensions/object balances, source identifiers, unknown records and correction history including `#RTRANS`/`#BTRANS`. Count final movements once. Specify applicable checksum behavior and diagnose unsupported records. Never auto-balance an unexplained difference. |
| Archive             | Calculate retention from the applicable fiscal/obligation basis and holds, not simply upload age. Preserve original electronic files, attachment multiplicity, readable keys and exact approved artifacts. Record storage/access geography and required evidence explicitly; a bucket region does not describe every processing location.                                                                          |

Keep system and processing documentation aligned with module ownership, capability versions, calculation rules and execution records. After changing a mapping or rule, identify affected report/filing versions and create explicit review work; shipping the fix does not repair or withdraw earlier artifacts.

Forecasts, management metrics and simulated drafts have separate identities and declared assumptions. They never change statutory books. An explanation must reconstruct the same contribution set and snapshot as the displayed figure, including exclusions and unresolved coverage.
