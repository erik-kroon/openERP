## Required distinctions

Sections 2.1–2.3 require all mandatory records for the advertised file type. A convenient subset cannot be advertised as a compliant whole format. Section 4 and the mandatory-record matrix distinguish **4I transaction import files** from **4E accounting exports**, even though both use `#SIETYP 4`. Recommended extensions are `.SI` and `.SE`, respectively (5.1).

A 4I file can transfer selected complete vouchers into another accounting program. It is not a complete-book export or a verified opening balance. A 4E export requires account and balance records and the applicable current/prior-year data. Existing accountant-review CSV is neither type.

## Serialization contract

| Fact | Specification location | Implementation consequence |
| --- | --- | --- |
| PC8 is code page 437, not UTF-8 or Windows-1252 | 5.8, `#FORMAT`, page 24 | Encode actual bytes. Refuse unrepresentable characters rather than replace or silently transliterate them. |
| One record per LF-terminated line; CRLF is permitted | 5.4–5.5 | Braces around voucher lines stand alone. Retain exact generated bytes and their hash. |
| Space/tab delimit fields; quotes delimit fields with spaces; embedded quotes have a preceding backslash | 5.7 | Reject embedded control characters (ASCII 0–31 and 127). Preserve field positions. Literal backslashes adjacent to delimiters need explicit interoperability cases. |
| Dot decimal, at most two fractional digits, no plus sign, optional leading minus | 5.9 | Use integer minor-unit arithmetic. Do not coerce money or voucher numbers to JS `number`. Reject unsupported currency scale instead of rounding. |
| Dates use YYYYMMDD | 5.10 | Validate real calendar dates before rendering. |
| Flag, identification, accounts, balances/vouchers appear in that group order | 5.12 | Deterministic output can further sort within permitted groups. |
| First record is `#FLAGGA 0`; an accumulating importer changes it after acceptance | `#FLAGGA`, page 23 | Never treat a generated flag as proof of import. Keep the original immutable export; store external observations separately. |
| `#FNAMN` is the legal company name | page 23 | Do not substitute a book display name for an unreviewed legal identity. |
| Voucher transaction amounts sum to zero | `#TRANS`, page 32 | Include entire vouchers and independently check balance before producing bytes. |
| Numbered vouchers are ordered ascending within their series | `#VER`, page 37 | Sort exact integer strings numerically; retain original series/number identities. |
| Missing positional fields before a later value use empty quoted fields | page 37 | Do not shift dates, text or signatures by dropping an intermediate field. |
| Credit balances are negative; current/prior-year numbers are 0/-1 | `#IB`, `#UB`, `#RES` | Account class and reviewed opening/year basis are required for 4E. Never infer first-year zero opening. |

The 4I mandatory identification records are `#FLAGGA`, `#PROGRAM`, `#FORMAT`, `#GEN`, `#SIETYP` and `#FNAMN` (pages 10–12). Account/object declarations are recommended even where optional. No `#IB`, `#UB`, `#RES` or other forbidden balance records belong in 4I. A 4E export has additional obligations; read the complete matrix rather than copy the 4I list.

## Existing consumer and next implementation slice

`accountant_review_packs` and `accountant_review_rows` already retain a bounded immutable ledger basis. Journal rows retain exact amounts, voucher/line IDs, posting dates, fiscal-year/period IDs, series/numbers and receipt/evidence lineage. `part=movement` identifies the report interval; `opening` and `excluded_after_end` must not be silently mixed into an interval transaction export. The pack basis pins currency and scale. Reuse those rows rather than query live vouchers during each download.

A useful first slice is explicitly labelled **SIE 4I transaction transfer**, not 4E/full bookkeeping export. It needs:

1. An immutable preparation command binding pack digest, explicit voucher/date selection, source-backed legal name, generator version and generation date. Verify scope, complete voucher boundaries, amount conservation and format support. Do not guess legal identity or actual-company applicability.
2. A pure exact encoder over captured facts, followed by a scoped persistence operation that rechecks the basis and retains the manifest and exact bytes. No network call or rendering in a financial transaction.
3. Durable list/read/download through REST, MCP and the review UI. Repeating the same command returns the same artifact; changed inputs conflict. New generation is distinct from external import acknowledgment.
4. Explicit current limitations: no full-book/4E export, no SIE import, no SIE 5, no provider transmission, no verified destination compatibility. These remain goal work, not silently omitted requirements.

## Failure and acceptance cases before implementation

- Wrong-book pack/evidence cannot be read or exported.
- A repeated request yields the same bytes/hash; changing a legal name or selection under the same key conflicts.
- Later postings, changed account names or reopened periods cannot change a saved artifact.
- Reject incomplete voucher selection, unbalanced lines, repeated series/number identities, inconsistent voucher metadata or unsupported amount scale.
- Refuse control characters, non-CP437 text and ambiguous string escaping instead of data loss.
- Preserve Swedish representable letters, quotes, empty positional fields, zero/minus signs, exact large amounts and numeric order beyond the safe JS integer range.
- Downloaded byte length/hash must equal its manifest. A structural parse is not semantic or destination acceptance.
- The official service at [sietest.sie.se](https://sietest.sie.se/) is documented in section 3.1. No file was uploaded in this review. External upload, independent validator evidence and any claim of SIE Group approval require their own gates. Section 3.2 distinguishes member-declared program approval from ordinary implementation.

New E2E/fixture work still requires D-09 approval. D-04 supplies legal/company/year/opening facts; D-08 supplies the supported profile and independent vectors. Do not mark END-06 complete from this research or from a future encoder alone.
