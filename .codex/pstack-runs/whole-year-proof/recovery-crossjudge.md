## Exact source corrections

1. **Candidate B invents receipt row locks.** Its reuse table says ordinary getReceipt retains a receipt share lock and db/posting.readCommandReceipt preserves share/update locking. In both checked trees, [readCommandReceipt](/Users/admin/openERP/apps/api/src/db/posting.ts:542) accepts an unused `_lock`, then performs SELECT without a lock clause. [getReceipt](/Users/admin/openERP/apps/api/src/application/posting.ts:1665) does lock the book and admits only `execute_change`, but passing `"share"` adds no receipt lock. A states this correctly. Preserve actual ordinary behavior; adding receipt locks would be a separate change, not recovery extraction.

2. **Removing wrapper book locks is insufficient.** [readOccurrenceStorage](/Users/admin/openERP/apps/api/src/db/source-retention.ts:185) and [listArchive](/Users/admin/openERP/apps/api/src/db/source-retention.ts:213) contain `FOR SHARE OF o`. B names this seam; A's proposal to reuse readStorage needs it grafted explicitly. [db/posting.readBook](/Users/admin/openERP/apps/api/src/db/posting.ts:78) also uses `FOR SHARE`; correctionChain calls it. An immutable read counterpart is needed wherever the chosen profile actually reaches it. Do not remove these locks from ordinary callers.

3. **Correction views have authority and clock semantics inside their read body.** [bundleView](/Users/admin/openERP/apps/api/src/application/posting-corrections.ts:881), when an approval exists without a completion receipt, checks current DB time, unconsumed reversal/replacement approvals, operator membership, actor admission and revocations. [readOperatorMembership](/Users/admin/openERP/apps/api/src/db/posting.ts:504) and [readActorAdmission](/Users/admin/openERP/apps/api/src/db/posting.ts:518) each lock share. B's blanket “no auth queries required” cannot mean no accounting membership/admission reads. Distinguish those scoped authority records from openerp_auth sessions/accounts, credentials and rate limits, which remain excluded. Preserve absence-of-admission semantics (`enabled !== false`) and expiry evaluation; do not present an expired restored approval as current or substitute capture time for DB time. A copied output is not equivalent to this owner.

4. **Database access checks are real dependencies.** [requireReportAccess](/Users/admin/openERP/apps/api/src/application/reports.ts:54) uses the complete reportTables list; source retention similarly uses [retentionTables](/Users/admin/openERP/apps/api/src/db/source-retention.ts:61), including source_uploads and command_receipts. [readTableAccess](/Users/admin/openERP/apps/api/src/db/commerce/access.ts:31) asks `has_table_privilege`, not merely per-column privileges. A proposed column-only grant set can therefore fail an unchanged owner gate. Bind the matrix to actual queries and access checks; do not silently remove checks or grant unrelated tables until a probe passes. Preserve the ordinary wrappers and decide any recovery-only narrower privilege check explicitly.

## Feasibility of shared reads and RLS

Shared extraction is feasible in source shape: there are private transaction-scoped decoders and projection functions already underneath the wrappers. The dedicated inspector can call extracted owned cores without moving report arithmetic, correction digest validation or original size/hash decisions into a second implementation. The required changes are not only signatures: some DB projections lock rows; original retrieval spans two admitted transactions around object IO; correction approval interpretation includes authority reads and time. A read-only type is a guard against mistakes, not DB enforcement. Native transaction mode/isolation support remains a frozen-adapter and isolated E2E gate.

The RLS overlay is feasible as a **separate destination-only phase**, not through the existing inventory function. [databaseInventory](/Users/admin/openERP/apps/api/scripts/operations/inventory.ts:34) refuses any pg_policy. Its schema hash also includes RLS/force-RLS flags and ACLs, and its return includes complete role inventory. Keep that source/restore baseline gate unchanged. First prove the base reconstruction; then verify an exact overlay using a separate strict verifier; finally remove it and rerun original schema/grant/role comparison where equality is claimed. Hashing an intended DDL file alone does not prove installed policies or effective grants.

Neither proposal specifies all installed-policy mechanics yet. Enumerate ENABLE/FORCE flags, policy command/role/predicates, joins and global authority dependencies, table/column/function ACLs and database settings. Creating a policy without enabling RLS does not enforce row scope. The policy-free baseline has no ordinary runtime RLS policies to “preserve”; enabling RLS can change ordinary row visibility. If temporary runtime policies are needed to preserve its prior semantics, they must be exact reviewed overlay entries, with ordinary CONNECT still fenced, and removed afterward. No PUBLIC/caller-GUC policy may widen inspector scope. Existing live authority checks must still run in ordinary routes after extraction.

The current restore's finalizer only observes disabled connections and zero capacity; it was written for a destination whose capacity stays zero. An inspection window that raises capacity must explicitly set it back to zero and observe that no owned inspection sessions remain. `datallowconn=false` is not evidence that already-open sessions were closed. Only owned new role/connection/overlay resources may be cleaned up; ambiguous cleanup is contained failure, never success.

Reject unchanged live getters under a read-only transaction, any global lock removal, runtime-role inspection, copied session activation, a global inventory RLS exemption, independent report/correction reimplementation, credentials-only egress fencing, and a partial request result called complete application recovery.

Independently specify exact values, IDs, byte hashes and expected refusal classes. A completed correction fixture alone would conceal the conditional membership/admission locks. Test ordinary authority race behavior remains unchanged as well as restricted inspection denial.

Success receipts must bind final observed quarantine and complete declared closure. Existing `.recovery.test.ts` selection must be explicit. Until those observations exist, the historical restore result remains `blocked-restricted-read-admission`; production custody, writer promotion and provider activation remain separate decisions.
